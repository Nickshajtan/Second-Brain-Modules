# Domain operation catalogue

Status: semantic contracts, not executable descriptors or production request schemas. Names below are proposed stable capability/operation names; their separation implements confirmed rules. [Invariants](domain-model.md), [glossary](glossary.md), [open decisions](open-decisions.md).

## Common contract applied to every row

The catalogue is normalized into common obligations and per-operation differences. Every slash-separated operation is a distinct operation with the corresponding capability; it is not a generic CRUD endpoint.

* Actor **H/A/S** means authenticated human/agent/service holding the named capability in the stated scope. **M** means the designated Membership Orchestrator or authorized human administrator; the Membership Service is always commit authority. **Admin** means independently authorized administration, including Owner; **Cleanup** is a scoped external service. Owner has supported administration but cannot bypass integrity. Ordinary-agent protected-Node restrictions apply even when its grant otherwise matches.
* **D** = direct after policy checks; **G** = exact Proposal/Approval required; **P** = direct or governed as current target Cluster policy decides. Direct is not permission-free. No operation acquires broader rights by nesting inside a batch or Proposal.
* All mutations require a durable idempotency key **K**, normalized request digest and audit intent/outcome. Replays require current authorization; same K/different digest → `IDEMPOTENCY_CONFLICT`; transient uncertainty is resolved by receipt, never blind retry. Key scope is instance/principal/operation/version; retention is D02. Creation uses registry/scope CAS and new-ID uniqueness. **C(x)** means expected revision(s) and on-disk hash for every touched aggregate x; missing/stale guards → `REVISION_CONFLICT`. Append-only record creation pins target revisions and checks uniqueness. All checks repeat under the commit boundary.
* Every operation authenticates instance/principal/session; unavailable or unauthorized existence-sensitive targets → `NOT_FOUND` with no names, counts, IDs, paths or diagnostic hints. An already authorized visible resource with an independently denied action may return sanitized `FORBIDDEN`; inaccessible endpoint failures remain concealed. Other common failures: `VALIDATION_FAILED`, `POLICY_CHANGED`, `INTEGRITY_FAILED`, `APPROVAL_REQUIRED`, `APPROVAL_REVOKED`, `DEADLINE_EXCEEDED`, `UNSUPPORTED_VERSION`, `REPAIR_REQUIRED`. No domain effect on validation/denial/CAS failure. Reject writes during unsafe recovery.
* Reads are **R**: no K/CAS, accept explicit committed snapshot/revision where relevant; current authorization before bytes and delivery, not only cache lookup. Audit allowed/denied access according to scoped read-audit policy; always audit privileged/history/export access and security denials. Redact audit bodies/tokens/private paths. Listing requires its own scoped enumeration authority; `node.read` is not cluster enumeration or history.
* **E(name)** means a proposed immutable, access-filtered committed event with transaction ID and affected authorized handles. Never emit success before commit. No event on denied attempt; security audit records the attempt. At-least-once outbox delivery and consumer dedupe are proposed. All mutation rows use common K/audit and all read rows use R/audit even when omitted in cells.
* Obsidian **N** = native note/Properties edit reconciled as unmanaged input; **V** = native/derived view updates after commit, not an authority; **A** = explicit Core/admin action or narrow adapter; **Q** = preserve raw conflict bytes, keep committed selection stable. Proposed display only, no plugin implemented.

Dangling edge policy: proposed retained tombstones plus explicit retire/remap during disposal; missing internal references reject new commits, unresolved unmanaged wikilinks remain diagnostics. No silent edge deletion, endpoint recreation or hidden endpoint stubs. Purge must inspect dependencies and selected snapshots under privileged authority.

Collection hierarchy permission default is proposed: parent scope limits descendant structural grants; an explicit deny or missing required ancestor traversal/structural permission prevents rename/reparent/remove, and reparent requires authority at both old and new parent. Inheritance never creates Node content or membership rights. Cluster policy must define its exact inheritance behavior before production hierarchy operations; do not assume a folder ACL or role ladder supplies it.

## Confirmed, proposed, open and excluded

Confirmed: invariant register I01–I21, distinct capabilities, all-or-none batch semantics, direct operations without mandatory Proposal, independent history and purge permissions. Proposed: exact operation names, event names, table modes marked “proposed”, create-admission delegation representation, reified Relation notes, snapshot identity and outbox delivery model. Open: D01–D09 and destination-specific policy choices. Non-goals: generic workflows, auto-fetching, agent planning, cross-instance transactions, universal plugins, production schemas or UI implementation in this phase.
