# Material open decisions

These are decisions that can change safety, storage authority or the authoring experience. Confirmed requirements are not reopened. Proposed defaults are **not Owner approval**. [Legacy Q register](../architecture/open-questions.md) remains historical; [reconciliation](../architecture/reconciliation-register.md) maps it.

| ID | Decision / recommended default | Risk and alternatives | Blocking milestone / deciding evidence |
|---|---|---|---|
| D01 | Deployment trust and authoring surface: trusted human vault; agents only authenticated Core interfaces, separate OS account/sandbox or scoped filesystem projection | Same-account agent reads `.git`, hidden notes, caches or plugin tokens regardless of Core ACL. A restricted folder inside full-readable vault is insufficient | Before any real agent data access; P03 must deny OS reads including Git/control/cache; human-vault and agent permissions reviewed |
| D02 | Durable control/journal/audit/outbox and transaction backend; propose single writer + durable coordination store + retained Git objects, committed-generation readers | Git/files/SQLite are not one transaction; raw editors race locks. Idempotency horizon, quotas, backup coherence and flush behavior require explicit choice, not inherited 30-day default | Before production storage/schema freeze; P04 crash matrix, backup/restore and Windows locking proof; otherwise narrow supported concurrency or revise authority with Owner |
| D03 | Approved graph semantics with independently revised Relations; propose Cluster graph snapshot selecting Relation revisions AND endpoint Node revisions | Pinning only Nodes silently changes approved meaning when a Relation changes. Alternatives: separately governed live edges or no approved graph traversal | Before promotion/graph production contracts; P02/P04 demonstrate revocation and edge edits without Node revision churn |
| D04 | Publication representation; propose new Node ID snapshot with derivation from source exact Revision; copying Relations/Assets explicit, never automatic | Same-ID multi-membership leaks private candidates into shared views; snapshot copies can leak private provenance/assets unless independently filtered | Before publication schema; representative private→Shared→private fork fixtures and user navigation review |
| D05 | Effect of Approval revocation on already selected revisions; propose fail closed until explicit authorized replacement selection | Automatic fallback may select outdated/revoked content; immediate removal can disrupt retrieval. Distinguish approval revocation from grant revocation | Before governed serving; policy fixtures for prior approval, concurrent revocation/commit and dependency selections |
| D06 | Retention, preservation routing, privacy erasure and backup/history treatment; propose no automatic destructive expiry until routing/preservation receipt is durable | Trash expiry is bounded deletion, never arbitrary purge. Git replicas/backups retain bytes. Retention must not accidentally preserve legally required erasures | Before disposal/purge enablement; Owner retention schedule, exact expiry scope, full recovery/erasure inventory and review of obligations |
| D07 | Standalone Relation file representation and editable Obsidian navigation; propose one Relation Markdown record with flat Properties and endpoint wikilinks as derived display | Native graph becomes endpoint→Relation-note→endpoint, not typed direct edge; generated sections risk dual authority/revision churn. Alternative narrow sidebar; changing canonical link authority needs explicit Owner decision | Before adapter commitment; P02 usability, rename, conflict and reverse-sync test |
| D08 | Basic Memory reuse boundary and license feasibility; propose separate read-only/scoped indexing component only if it avoids more work than adapter adds | Native writes bypass governance; AGPL obligations and dependency footprint need review; boundary does not by itself settle license obligations | Before dependency adoption/distribution; P01, release-pinned source trace and legal review of actual integration |
| D09 | Production contract IDs, schema namespace, capability names and generation profile | Existing example IDs are deliberately invalid for publication; premature field freeze would harden obsolete embedded Relations | Before production contracts; Owner namespace choice, minimal reviewed fixtures, unchanged Python/Ajv parity |
| D10 | Policy composition across memberships, selected Cluster views and Collection hierarchy; propose explicit deny-overrides among applicable policies, no implicit permission inheritance, with Owner/admin paths represented explicitly | “Applicable” must be defined: evaluating an unrelated private Cluster as a blanket deny can hide intentionally shared views, while union-of-grants can leak protected content. Content write protection remains unconditional for ordinary agents regardless of read composition | Before P03 model acceptance and production policy contracts; truth table for multi-membership reads, independent publication snapshots, historical selection, ancestor rights and cross-Cluster Relations |

Non-blocking refinements stay in implementation backlogs: exact UUID choice, UI labels, optional transports, ranking, schema deprecation cadence. They do not justify building infrastructure now.
