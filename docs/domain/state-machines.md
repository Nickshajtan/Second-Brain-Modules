# Domain state transitions — M1.2

These are domain transitions, not a generic workflow runtime. [Accepted rules](accepted-decisions.md), [invariants](invariant-register.md), [coverage/deferrals](../contracts/contract-coverage-matrix.md) govern their interpretation. Only M1 create/read/atomic commit/retry are implemented. All other rows describe intended transitions under named prerequisites. Policy can allow direct operations; Proposal/Approval is never universally mandatory.

| Transition / status | Operation / actor capability | Preconditions and authorization | Result / revision impact | Audit / receipt and cross-resource effects |
|---|---|---|---|---|
| No Node → initial admitted Node; M1 subset | node.create; creator + trusted membership.admit | Registered explicit type/version, valid content, authorized private active Cluster, new resource ID, current policy and generation | Head 1 plus immutable NodeRevision snapshot and sole Membership; explicit node_id independent of request_id, legacy omission documented | One receipt and atomic publication; no orphan; no implicit publication |
| Head N → head N+1; confirmed M2 | node.update; operation-specific update | Editable ownership/full protection set, current authority/CAS; full immutable prior bytes and historical receipt resolution first | New immutable NodeRevision and updated head; selected approved pointer unchanged | Exact mutation receipt; no implicit membership or approval changes |
| Existing head → independent candidate; confirmed M6 | node.propose_revision; candidate authority | Visible exact base and authorized candidate scope; protected selection not overwritten | Candidate immutable content + exact Proposal; head/selection unaffected unless separately authorized | Proposal/digest/revision evidence; no approval/execution granted |
| Candidate → approved selection; minimum Node model confirmed M6 | approval.issue then membership.select_revision; distinct approval/selection authorities | Exact Proposal/parameters/revisions, current unrevoked policy, immutable bytes present, CAS | Cluster-specific Membership approved pointer changes; Node head need not change | Approval immutable evidence; consumption/selection transaction guarded; Relation breadth remains O2 |
| Selected revision → missing bytes; confirmed fail closed | node.read; selected-view authority | Selection reference known only after authorization; bytes missing | No fallback to candidate/newer head | Sanitized failure, no hidden revision identifiers |
| Exact revision → history delivery; confirmed shape, M2 runtime absent | node.revision.read / relation.revision.read; separate history capability plus current resource disclosure | Explicit typed RevisionRef, instance match, retained exact snapshot, current permission; Relation plus endpoints | Immutable revision record in ReadResult at pinned generation; no mutations | Current authorization audited under later policy; no raw Git history shortcut |
| No membership → admission; confirmed | node.create initial delegation or membership.attach by designated authority | Destination admission, current Node protection/all memberships, no unauthorized disclosure | Separate Membership relationship; content revision unchanged | Atomic creation admission in M1; existing-node attach M6; no publication inferred |
| Membership active → detached; confirmed M6 | membership.detach; designated authority | Recheck full protection set; last membership safely routes; never detach-to-edit bypass | Membership changes, Node bytes unchanged; no orphan or hidden membership disclosure | Own mutation evidence; batch cannot use detachment to erase protection |
| Relation absent → revision 1; M1 subset | relation.create; owner relation.create and both endpoint reads | Registered predicate/version, new ID, one owner Cluster, explicit same-instance accessible endpoints | Relation head independent of Nodes; receipt logical RevisionRef; full RelationRevision persistence still M2 | No inverse/Node revision side effects; receipt currently verifies creation against unchanged head |
| Relation N → N+1; confirmed M2 | relation.update; owner policy capability | Independent CAS, endpoint changes reauthorize endpoints, immutable snapshot/receipt linkage first; ownership transfer not generic update | New exact RelationRevision snapshot, independent head; no endpoint revision increments | Own receipt and current policy checks; approved Relation assertion selection O2 |
| Relation active → retired; confirmed M2 | relation.retire (wire relation.delete requires naming reconciliation) | Owner authority/CAS and retained dependency checks | Retired Relation revision; no Node deletion/revision change | Preserve old edge bytes; no automatic approved graph fallback |
| Active ↔ archived; confirmed M7 | node.archive / node.unarchive; distinct lifecycle authorities | Full protection/membership/current-policy guards; ordinary agent cannot mutate protected knowledge | Lifecycle revision; Cluster membership retained; validity/approval independent | Lifecycle receipt; active queries omit archived unless explicit |
| Editable knowledge → pending disposal; confirmed M7 | node.delete / catalogue node.request_disposal; disposal authority | Eligible editable Node, protection/current policy and CAS | Pending disposal, not physical erasure | Durable disposal request retains original ownership/membership metadata |
| Pending → Trash / private Global Archive preservation; confirmed M7 | disposal.route / disposal.preserve_copy; authorized cleanup plus source disclosure/destination admission | Exact routing, retention/hold/preservation evidence and destination policy | Isolated recoverable Trash and/or independently identified Archive copy with provenance | Preservation durable before expiry; no implicit grants; O3 details remain open |
| Trash → restored; confirmed M7 | node.restore; current restore/admission | Retained bytes, present destination rights and collision checks | Restored identity/content according to explicit later protocol; never restore old grants implicitly | Recovery lineage and new admission receipt; identity collision rules finalized before activation |
| Trash → expired / retained bytes → purge; partly OPEN M7 | trash.expire versus node.purge; separate strong capabilities | Owner O3, explicit erasure scope, holds/reference closure, durable required preservation | Logical removal scoped by reviewed policy; never promises Git/backup physical erasure | Separate irreversible-action audit/receipt; backup/history destruction requires separate reviewed procedure |
| Approval active authority → revoked; confirmed record, O3 effect OPEN | approval.revoke; independent privileged authority | Exact Approval, current policy/CAS and in-flight checks | Separate immutable revocation; Approval record unchanged; selected content effect unresolved | New revocation evidence; commit/delivery repeats current checks |
| Batch input → prepared objects; M1 | batch.submit; union of constituent authorities | Canonical schema, exact digest/IDs, instance match, policy/admission/CAS under writer boundary | Unpublished Git objects; no domain effects visible | Prepared objects are not committed success; no nested partial commits |
| Prepared → published; M1 | conditional managed-ref publication; trusted Core | Expected managed generation/ref unchanged; all operations validated | One committed generation containing effects/request/receipt together | CAS failure leaves no committed effects; index is rebuildable, not second authority |
| Published → exact retry; M1 create-only | batch.submit / execute; original actor with current operation permissions | Original normalized request/key identity; durable integrity-checked receipt; current auth | Return original receipt without reexecution; changed request conflicts | M2 must resolve immutable original effects/admission instead of current heads; integrity not removed |
| Human raw file edit → unmanaged/candidate/conflict; confirmed M3, timing O1 | reconciliation.scan; scoped trusted human/service | Safe paths/raw bytes, base generation/hash; protect approved state | Preserve invalid/conflicting bytes and diagnostics; no automatic canonical promotion | Restricted evidence, no silent discard, no assumed immediate synchronization |
| Validated plan → adopted revision or preserved conflict; confirmed M3 | reconciliation.commit plus all underlying operation rights | Exact raw/base hashes, current policy/CAS and O1 handoff; invalid bytes retained | Underlying atomic Node/Relation/admission/candidate effects only if all valid | Receipt links raw/base/committed hashes; external editor is outside transaction boundary |

Collections change only organizational records/references, never Node content, membership or approvals; parent changes remain in one Cluster and acyclic. Assets remain independently shared; deletion does not imply garbage collection. Committed events are immutable scoped facts, while external delivery/status records are independently authorized and may be at least once. Core executes neither event subscriptions nor generalized workflows.
