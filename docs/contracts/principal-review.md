## Confirmed findings

### P2 — Unknown TypeScript families can bypass canonical validation

In `packages/typescript/validation.mjs`, the validator table is an ordinary object.
The original lookup accepted inherited functions as validators. Calling
`contracts.validate('toString', {malformed: true})` or using `constructor` returned
the malformed payload successfully without invoking Ajv. TypeScript's declared
family union does not protect JavaScript callers or unchecked runtime inputs.

Fix: require an own property before retrieving the validator. The regression
`test_ajv_rejects_unknown_prototype_family_names` checks five unknown family names
and confirms that a known family still produces canonical `VALIDATION_FAILED`.

### P2 — Strict Python JSON loading silently creates infinity

In `packages/python/second_brain_contracts/validation.py`, `parse_constant` rejected
literal `NaN` and `Infinity`, but did not handle exponent overflow. Before the fix,
loading `{"value":1e999}` returned `{'value': inf}`. This violated the documented
strict loader boundary by creating a non-finite decoded number. Later canonical
`validate()` rejects it; this finding concerns loading itself, not a demonstrated
bypass of canonical payload validation.

Fix: a finite-number check in `parse_float` rejects overflow during decoding.
Regressions cover positive, negative and nested overflow, plus finite large
floats, a fractional value and an integer preserved without a float conversion.

## Boundaries, unconfirmed concerns and next slice

- No broken public import, incomplete current bundle, unresolved current reference,
  generated byte drift or current version mismatch was reproduced by the executed
  checks. Production code was not changed for those suspicions.
- Additional finite scalar/list round-trip probes on Node properties, including
  booleans, empty lists, the maximum safe integer and a small finite float, found
  no loss of JSON value. Direct generated types still approximate canonical
  constraints and must not replace the validation adapters.
- The nine semantic fixtures deliberately pass structural validation. Approval
  digest equality, interval ordering, Collection cycles, CAS, cross-instance batch
  consistency and similar obligations remain unenforced runtime semantics. Their
  structural acceptance is documented, not a new defect to fix in this scope.
- Compatibility tests are synthetic; there is no released predecessor corpus.
  Hash manifests detect drift, not publisher identity. Runtime declarations pin
  top-level dependencies; reproducible transitive provisioning requires the recorded
  locks or a derived consumer lock. Dist-free delivery still needs a release and
  provisioning policy. None of these policies was implemented here.

Recommended next slice: extend the automated differential conformance corpus with
schema-boundary mutations and isolated TypeScript consumer compilation, and use a
real previous/current bundle pair for compatibility testing when a release exists.
Keep semantic enforcement and artifact delivery as separately scoped work.
