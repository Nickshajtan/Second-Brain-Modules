# Evolution and authority

Canonical sources: [eight JSON Schema resources](../../contracts/registry/v1.json); semantic sources: [domain invariants](../domain/domain-model.md), [operation catalogue](../domain/operations-catalog.md), [production operation mapping](operations.md). Generated Python/TS output is never hand-edited. No reverse generation from Pydantic, TS or OpenAPI is permitted.

Change process: edit canonical schema and semantic documentation together; classify both structural and behavioral compatibility; update exact version/registry IDs for a released change; add portable valid/invalid fixtures and explicit semantic obligations; regenerate with existing pinned tools; run independent Python/Ajv validation, Pydantic round-trips, TS checks and byte/file-set drift gates. Generator upgrades are separate reviewed changes from schema evolution. The baseline resources stay Draft 2020-12 with ordinary local refs, closed objects and tagged object unions. A standard `not` newline guard extends primitive validation without a custom keyword; canonical validators enforce it even when generated types approximate it.

Never reuse IDs or reset logical revision counters during conversion. Persisted-record migration must be explicit, with source/target versions, inventory and provenance/ID mapping, dry-run plan and recoverable application appropriate to its later runtime. **No migration or storage engine is implemented here.** Retain old released schema bundles and package pins for the supported compatibility window; its exact duration is a future release policy, not silently fixed to an old proposal.

O1–O4 remain Owner decisions: synchronization timing, breadth of approved assertions, retention/revocation effects and multi-membership read composition. These contracts carry the confirmed data needed for each choice but do not choose its algorithm. Relation selection is optional and independent. Approval records never overwrite Review or historical revocation. Disposal retains source ownership/Cluster snapshot, routing/preservation evidence, policy reference/hold/optional expiry, without claiming all Git history/backups are erased.

Baseline limitations/deferred families: the complete operation catalogue is broader than this task's minimum request surface. No dedicated schemas/handlers for purge/Trash expiry, arbitrary grant-management commands, remote transport bindings, runtime jobs, generic nested workflows or graph snapshot engine are delivered. Existing control/disposal records support later explicit operations; their final retention/deployment semantics remain unresolved. Atomic batch entries are a bounded **flat mutation list**, no recursively nested batch or cross-instance transaction. Producers needing nested composition must flatten and validate before submission in a later implementation, not assume nested commits exist.

No known family required by task.md is replaced by a placeholder. Remaining cross-record checks are intentional semantic obligations, not incomplete structural validation: registry membership/type constraints; principal authentication/Owner bootstrap; membership/protection authorization; source/destination disclosure; exact approval digest/target matching; identity/revision linkage; validity ordering; Collection cycles/Cluster matching; retained Asset references/budgets; import remapping; current-policy non-discovery; batch uniqueness/CAS/atomicity/receipts. The [semantic corpus](../../tests/fixtures/contracts/semantic.json) records representative invalid combinations without pretending JSON Schema compares databases or executes transactions.
