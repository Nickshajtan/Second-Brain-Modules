# Domain/API contract coverage — M1.2

Current exhaustive operation inventory reconciles the [semantic catalogue](../domain/operations-catalog.md), all 36 discriminated production request variants, extra history/event/type/predicate reads required by the domain, and the public M1 bootstrap/generation boundary. Each slash variant is a separate row. Stable CAP IDs are domain identifiers; catalogue names remain proposed unless backed by an exact operation discriminator. Similar names below are **not** wire aliases.

**Interpretation:** semantic CONFIRMED means the underlying boundary is accepted, not that every historical parameter/default is approved. `partial` means an exact canonical operation request exists or a bounded M1 host/batch runtime exists; record-only coverage without a dedicated request remains intentionally deferred; `intentional defer` means no dedicated request/runtime exists and activation is blocked by the named dependency (record structures may already exist). No row proves deployment verification. All rows inherit [API conventions](api-catalog.md), invariant enforcement and current-policy rechecks. Schema shorthand is exact: **O** = `https://github.com/Nickshajtan/Second-Brain-Modules/contracts/1.0.0/operations.schema.json`; **T** = same namespace `transaction.schema.json`; **K/C/G/S/A** = `knowledge/control/governance/snapshots/authoring.schema.json`. A `$defs` suffix resolves under that exact resource. Python modules import from `generated.v1`; TypeScript declarations import from `packages/typescript/generated/v1`.

Result codes are a permitted typed envelope, not operation-specific payload completeness. Mutation `T#/$defs/CommittedReceipt` / read `T#/$defs/ReadResult` are shared; missing dedicated results are explicitly noted. Tests labelled “structural corpus” establish shape only. Existing Core evidence is `tests/test_core_m1.py`; deployment/real MCP is unverified for every row.
